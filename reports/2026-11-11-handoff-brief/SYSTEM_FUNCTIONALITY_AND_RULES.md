# QRL-Lab — λειτουργικότητα, αρχιτεκτονική, οδηγίες και αρμοδιότητες

**Ημερομηνία αποτύπωσης:** 11/11/2026. **Συντάκτης:** Codex, εργασία J493, κατόπιν M-20261111-051. **Αποδέκτης:** Κώστας και το επόμενο μοντέλο που θα αναλάβει.

Το αρχείο συμπληρώνει το [BRIEF_FOR_OTHER_MODEL.md](BRIEF_FOR_OTHER_MODEL.md), το οποίο διαβάστηκε πρώτο. Εκεί βρίσκονται οι στόχοι και η αναλυτική αφήγηση της αποτυχίας ανάκτησης των πειραμάτων. Εδώ καταγράφεται πώς λειτουργεί το σύστημα, τι έχει ζητηθεί, τι έχει υλοποιηθεί και ποιος ελέγχει κάθε ενέργεια. Οι τεχνικές λεπτομέρειες και οι παραπομπές περιλαμβάνονται επειδή ζητήθηκε αρχείο παράδοσης· οι καθημερινές απαντήσεις εξακολουθούν να πρέπει να είναι σύντομες και κατανοητές (M-20261110-018, M-20261111-051).

**Όριο τεκμηρίωσης:** έγινε ανάγνωση σημερινού κώδικα, των παρακάτω κανόνων, των οδηγιών c4 και καταγεγραμμένων περιστατικών. Δεν έγινε δοκιμή κάθε κουμπιού σε browser, έλεγχος όλων των υπηρεσιών στον host ή εξαντλητική επαναανάγνωση όλου του ιστορικού. «Υλοποιημένο» σημαίνει ότι υπάρχει αντίστοιχος κώδικας ή καταγραφή υλοποίησης· δεν σημαίνει ότι επιβεβαιώθηκε σήμερα η λειτουργία του στον browser. Η τρέχουσα εκτέλεση πειραμάτων δεν επαληθεύτηκε σε αυτή την εργασία. Όπου λείπει τεκμήριο γράφεται **άγνωστο**.

## 2. Αρχιτεκτονική πειραμάτων και κύκλος c4

### 2.1 Κοινή αλυσίδα εγκυρότητας

1. Καθορίζεται πριν από το run αμετάβλητο spec: κώδικας/entrypoint, seeds/split, arms, φόρτος, budget/όρια και έξοδοι. Η έγκριση καλύπτει αυτό ακριβώς το περιεχόμενο/hash (`tools/launch_run.py`, `tools/labdb.py`, `AGENTS.md`, PLAN §6).
2. Η έγκριση μπορεί να είναι συγκεκριμένη κάρτα, child spec εγκεκριμένου sandbox/περιβλήματος ή η στενή προσωρινή προέγκριση c4. Δεν καταργούνται spec, audit και έλεγχοι επειδή δεν χρειάζεται νέα κάρτα (`tools/envelope.py`, `tools/c4_autonomy.py`, `docs/DECISIONS.md`).
3. Εκκίνηση μόνο μέσω launcher. Καταγραφή `.lab/runs/<run_id>/`: spec entry, commit, `output.log`, `launcher.json`. Τα payloads/working copies αποθηκεύουν αριθμούς/checkpoints στις δηλωμένες εξόδους (`tools/launch_run.py:1`).
4. Ανεξάρτητο review των αλλαγών που παράγουν αποτελέσματα, υγιείς baselines και ίσοι προϋπολογισμοί. Tuning/checkpoint selection στο validation, κοινά paired traces, αρκετά seeds και διαστήματα αβεβαιότητας. Test μία χρήση μετά freeze (`AGENTS.md`, `.claude/skills/rl-eval-protocol/SKILL.md`, κύριο c4 §6).
5. Ολοκλήρωση σημαίνει πραγματική διεργασία/έξοδος και αριθμητικό αποτέλεσμα με τεκμήριο. Καταχώριση DB `running` ή receipt υποβολής δεν αρκεί. Το περιστατικό c4 το αποδεικνύει (`M-20261111-039/042`, `.lab/c4/execution/j480/host_proof.json`).
6. Ενημέρωση μητρώου και handoff. Αρχειοθέτηση αριθμών πίσω από πίνακες/γραφήματα μέσω αντιγραφής· τα spent tests δεν ξανανοίγουν για να ξαναπαραχθεί αναφορά (`docs/rules/experiments.md`, `tools/results_collect.py`).

### 2.2 Διαχωρισμός εργασίας και πόρων

- Πυρήνες **0–3** dashboard, **4–7** agents/tests, **8–39** simulation· ο συντονιστής δεν καρφώνεται σε CPU. Δεν υπάρχει CPU-minute cap για tests (`docs/researcher_requirements.md` G8, `docs/claude-memory/core-split.md`). Ο launcher έχει default simulation affinity `8-39` και thread defaults, με ελέγχους διαθέσιμων CPUs (`tools/launch_run.py:37`).
- Για c4, **32 κοινές θέσεις**, με προτεραιότητα στην 1.3. Αυτό είναι χωρητικότητα πειραμάτων, όχι `max_workers` συνεδριών μοντέλων (`M-20261111-027`, `docs/DECISIONS.md` C479).
- Κάθε run detached, με log/heartbeat. Watchdog script ανά **15′**, heartbeat παλαιότερο των **10′** → έλεγχος ότι η αρχική διεργασία πέθανε, μία επαναποστολή· δεύτερη νέκρωση → decision agent. Πρόκειται για απαίτηση του `QRL-Lab_c4_no_blocking.md` §2.3, όχι πιστοποίηση ότι υλοποιήθηκε ήδη για όλα τα c4 runs.
- Το παλαιότερο `tools/supervisor.py` καλείται από user timer ανά **2′**, με δικούς του περιορισμούς auto-resume· δεν αποδεικνύει ότι έχει εγκατασταθεί ο παραπάνω c4 watchdog (`docs/rules/supervisor.md`).
- Παλαιότερα cycles: χωριστά Claude/Codex working copies (`code-tuning`, `code-tuning-astra`, άλλα c19/c20/c22/c23). **c4: ένας νέος working copy `code-poisson-c4/` από `code-poisson-c345/`**, χωρίς τροποποίηση του c345. Η ειδική νεότερη οδηγία υπερισχύει της γενικής απαίτησης ανταγωνιστικών κλάδων για αυτόν τον κύκλο (`docs/STATE.md`, κύριο c4 §0, M-20261110-030).

### 2.3 Φάσεις και πύλες c4: τι ζητείται τώρα

Η σειρά ισχύος είναι: τελευταίο κύριο c4 md → `QRL-Lab_c4_autonomy.md` → `QRL-Lab_c4_no_blocking.md` και μεταγενέστερες συγκεκριμένες εντολές. Ο ενεργός κύριος ορισμός είναι η έκδοση με τη γραμμή «πυκνό δίκτυο με ιστορικό (§2.3)» (`Mds με νέες οδηγίες Κώστα/QRL-Lab_cycle4_instructions__1_-1.md`, autonomy εισαγωγή). Παλιές αριθμημένες παραλλαγές δεν διαγράφονται από agent· τις χειρίζεται ο Κώστας (autonomy §3.8).

| Στάδιο | Περιεχόμενο / κανόνας συνέχειας | Πηγή |
|---|---|---|

## 6. Skills: τι υπάρχει, σε ποιον ανήκει και πότε χρησιμοποιείται

### 6.1 Τι σημαίνει «διαθέσιμο»

Skill είναι αρχείο οδηγιών `SKILL.md`, όχι αυτόνομο μοντέλο, ενεργός agent ή εγγυημένη σύνδεση υπηρεσίας. Διακρίνονται: **project skill στο δίσκο**, **host/user skill**, **skill που δηλώνεται σε αυτή τη συνεδρία**, **cache plugin που μπορεί να μην είναι ενεργό**. Απαγορευμένες ενέργειες δεν γίνονται επιτρεπτές επειδή τις αναφέρει skill (`AGENTS.md`, κατάλογος skills της συνεδρίας J493, `tools/installed_view.py`).

Το `tools/installed_view.py` ανιχνεύει skills/plugins/agents/hooks με κανόνες διαδρομών. Δεν βλέπει κατ’ ανάγκη όλα τα nested synced/system/plugin skills· η εμφάνισή του δεν είναι πλήρης απόδειξη πρόσβασης σε εργαλεία. Η παρούσα απογραφή βασίζεται επιπλέον σε στοχευμένη καταμέτρηση `SKILL.md`, χωρίς ανάγνωση secrets/config credentials.

Οι παλιές project ρυθμίσεις περιορίζουν connectors (M-20261028-004/006, `docs/dashboard_requests_20261028.md`), ενώ ο κατάλογος της παρούσας Codex συνεδρίας εμφανίζει Google/Sites/Pets skills. Αυτό δείχνει διαφορετικές επιφάνειες διαθεσιμότητας· δεν αποδεικνύει ότι άρθηκε η παλιά πολιτική για κάθε Claude task. Δεν έγιναν νέες συνδέσεις, εγκαταστάσεις ή εξωτερικές εγγραφές για αυτή την αναφορά.

Πριν το επόμενο μοντέλο δράσει, πρέπει να ξεκινήσει από τη σημερινή `docs/STATE.md`, το προηγούμενο brief και τις νεότερες εντολές του Κώστα. Αυτό το αρχείο είναι αποτύπωση, όχι νέο frozen spec, άδεια πειράματος ή αλλαγή πολιτικής. Η παρούσα εργασία δεν εκκίνησε runs, δεν άλλαξε καταστάσεις πειραμάτων στη DB, δεν άλλαξε κανόνες/ρυθμίσεις και δεν έκανε push (scope J493).

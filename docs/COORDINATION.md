# Συντονισμός QRL-Lab v0.3: συντονιστής κατά απαίτηση, Claude ή Codex

Σκοπός: να μη χρειάζεται μοντέλο ανοιχτό όλη μέρα, να διαλέγεις εσύ τον συντονιστή, και όταν τελειώσει το όριο του
ενός να συνεχίζει αυτόματα ο άλλος, χωρίς να χαθεί η συνέχεια.

## 1. Η αιτία του κόστους, σε δύο γραμμές
Κάθε κλήση εργαλείου μέσα σε μια απάντηση ξαναστέλνει όλο το ιστορικό της συνεδρίας. Με ιστορικό εκατοντάδων χιλιάδων
tokens, ακόμα και μια «ζεστή» απάντηση με 20 κλήσεις εργαλείων κοστίζει πολύ. Όταν η cache έχει λήξει (έλεγχος
κάθε ώρα, `--continue`), όλο το ιστορικό ξαναγράφεται στην cache, κάτι που κοστίζει ακόμη περισσότερο.
Opus 5.5 (τιμές API ανά εκατομμύριο tokens): είσοδος $4, έξοδος $20, εγγραφή cache $5 (5′) ή $8 (1 ώρα),
ανάγνωση cache $0.20.

## 2. Πώς δουλεύει τώρα
```
dashboard ──► .lab/lab.db ──► tools/dispatcher.py (Python, 0 tokens όσο περιμένει)
                                   │  μόνο όταν υπάρχει δουλειά:
                                   ├─► claude -p …   (Opus, effort medium)         ή
                                   └─► codex exec …  (μοντέλο από ~/.codex/config.toml)
                                        context: docs/STATE.md + τελευταία μηνύματα του θέματος + νέο μήνυμα
                                   ◄── τελική απάντηση → δημοσιεύεται στο θέμα, με υπογραφή «— Claude · opus · 3′ · ≈$0.40»
```
- **Τι ξυπνά τον συντονιστή:** (1) μήνυμά σου, (2) απόφασή σου σε αίτημα, (3) τέλος μιας παρτίδας πειραμάτων
  (όλα τα runs ενός εγκεκριμένου αιτήματος). Δεν γίνονται πλέον ωριαίοι έλεγχοι από μοντέλο.
- **Συνέχεια μέσα σε ένα θέμα:** αν το επόμενο μήνυμα έρθει όσο η cache είναι ζεστή (Claude: έως ~54′ σε συνδρομή,
  ~4′ σε credits· Codex: 15′) και το context είναι κάτω από 120k tokens, συνεχίζει την ίδια συνεδρία (φθηνό).
  Αλλιώς ξεκινά καθαρά από το `docs/STATE.md`. Έτσι η «εναλλαγή συνεδρίας» γίνεται μόνη της, χωρίς cron.
- **Ερώτηση στον άλλο:** `tools/ask_peer.py` (Claude→Codex ή Codex→Claude). Τρέχει μόνο για ανάγνωση, καταγράφεται,
  και με `--key` συνεχίζει την ίδια συζήτηση (π.χ. δεύτερος γύρος σε council).

## 3. Επιλογή συντονιστή και αυτόματη ανάληψη
- **Πάνελ «🧭 Συντονιστής»** (αριστερή στήλη του dashboard): Claude ή Codex· αυτόματη ανάληψη· παύση· αν επιτρέπονται
  πληρωμένα credits. Δείχνει και πόσο από το 5ωρο και το εβδομαδιαίο όριο του Claude έχει χρησιμοποιηθεί,
  όπως το αναφέρει το ίδιο το CLI μετά από κάθε εργασία.
- **Για ένα μόνο μήνυμα:** γράψε στην αρχή `@codex` ή `@claude`.
- **Όταν ένας φτάσει το όριο:** η ίδια εργασία ξανατρέχει από τον άλλο, με σημείωση «συνέχισε· δες το θέμα,
  το `git status` και το STATE.md». Ο πρώτος σημειώνεται «εξαντλημένος» ως την ώρα επαναφοράς που ανέφερε, και μετά
  επιστρέφει μόνος του η επιλογή σου. Αν είναι και οι δύο στο όριο, το μήνυμα περιμένει και συνεχίζει αυτόματα.
- **Πληρωμένα credits:** αν ο Claude αναφέρει ότι χρεώνει extra usage, η απάντηση δημοσιεύεται και οι επόμενες
  εργασίες πάνε στον Codex για μία ώρα (εκτός αν το επιτρέψεις στο πάνελ). Για πλήρη προστασία κλείσε το extra usage ή
  βάλε μηνιαίο όριο στο claude.ai → Settings → Usage· τότε το όριο γίνεται σφάλμα και ενεργοποιεί την ανάληψη.
- Από τερματικό (μόνο εσύ): `python3 tools/dispatcher.py status | set coordinator codex | clear claude`.
- Άσκηση ανάληψης χωρίς να περιμένεις πραγματικό όριο: `python3 tools/dispatcher.py exhaust claude 10`.

## 4. Η κοινή μνήμη (την διαβάζουν και οι δύο)
| Αρχείο | Ρόλος | Ποιος το γράφει |
|---|---|---|
| `AGENTS.md` | κοινοί κανόνες· ο Codex το διαβάζει μόνος του, ο Claude μέσω `@AGENTS.md` | εσύ / με έγκριση |
| `docs/STATE.md` | **το handoff**: στόχος, τι τρέχει, τι περιμένει εσένα, επόμενα βήματα, γεγονότα με δείκτες, «μην ξανακάνεις» (≤150 γραμμές) | ο συντονιστής, στο τέλος κάθε εργασίας |
| `docs/DECISIONS.md` | αποφάσεις που δέχτηκες | ο συντονιστής |
| `docs/journal/<ημέρα>.md` | μία γραμμή ανά εργασία (ποιος, μοντέλο, κόστος, αποτέλεσμα) | ο dispatcher (χωρίς μοντέλο) |
| `docs/INDEX.md` | ευρετήριο **όλων** των .md: διαδρομή, τίτλος, περιγραφή μιας γραμμής, ημερομηνία | `tools/build_md_index.py` (χωρίς μοντέλο, ανανεώνεται μόνο του) |
| `docs/claude-memory/` | αντίγραφο της auto memory του Claude, για να τη βλέπει και ο Codex | ο ίδιος script |

Τα .md που ήδη υπάρχουν στους φακέλους μένουν όπως είναι: μπαίνουν στο INDEX, και ο συντονιστής τα βρίσκει με
`grep -i "<θέμα>" docs/INDEX.md` αντί να τα διαβάζει όλα. Για καλύτερη περιγραφή σε ένα αρχείο, βάλε στην αρχή του:
```
---
description: μία γραμμή για το τι περιέχει
---
```
Φάκελοι εκτός `~/qrl-lab` (μόνο για ανάγνωση): μία διαδρομή ανά γραμμή στο `docs/index_roots.txt`.

**Πειράματα:** το `docs/EXPERIMENTS.md` είναι το μητρώο κάθε παρτίδας: τι είναι, πού τρέχει, πού είναι τα
αποτελέσματα, η κατάσταση και το αποτέλεσμα. Το ενημερώνει ο συντονιστής όταν μια παρτίδα προτείνεται, ξεκινά, τελειώνει
ή αναλύεται. Τα runs που ξεκινούν από το `tools/launch_run.py` υπάρχουν επιπλέον στη βάση (καρτέλα 📈,
`launch_run.py list`), ανεξάρτητα από κάθε μοντέλο. Γι' αυτό κάθε νέο πείραμα ξεκινά μόνο από εκεί.

## 5. Ασφάλεια (όπως πριν)
- Claude: οι κανόνες του `.claude/settings.json` ισχύουν και σε headless (auto mode· ό,τι θα ζητούσε άδεια
  απορρίπτεται και αναφέρεται στο θέμα με 🔐). Codex: `workspace-write` sandbox (δεν γράφει εκτός `~/qrl-lab`) και
  κανόνες `~/.codex/rules/qrl-lab.rules` (απαγορεύονται kubectl αλλαγές, helm, push, sudo, crontab, `labq decide`,
  `dispatcher set`).
- Οι εγκρίσεις πειραμάτων μένουν στο `tools/launch_run.py`. Το dashboard μένει μόνο στο 127.0.0.1.
- Ο συντονιστής δεν αλλάζει ρυθμίσεις, cron ή υπηρεσίες. Επανεκκινήσεις: systemd (`Restart=on-failure`).

## 6. Λειτουργία
- Κατάσταση: πάνελ στο dashboard, ή `python3 tools/dispatcher.py status`.
- Logs: `journalctl --user -u qrl-dispatcher -n 50`.
- Παύση όλων: πάνελ → «Παύση», ή `systemctl --user stop qrl-dispatcher`.
- Επιστροφή στο παλιό σύστημα: `systemctl --user disable --now qrl-dispatcher` και
  `bash tools/start-coordinator.sh`. Τα αρχεία της v0.3 δεν αλλάζουν τίποτα από τα παλιά (τα αντίγραφα ασφαλείας
  του installer είναι στο `.lab/backup-v03-*`).
- Συνομιλία με τον Claude από κινητό ή τερματικό είναι ακόμα δυνατή (`claude` στο `~/qrl-lab`)· μια ανοιχτή αλλά
  αδρανής συνεδρία δεν κοστίζει. Απλώς μην την ξεκινάς με `--plugin-dir ./tools/lab-bridge`, γιατί τότε θα
  έπαιρνε και αυτή τα μηνύματα του dashboard.

## 7. Μεταφορά του project σε άλλο μηχάνημα
Τα zip των kit (v0.2, v0.3.x) **δεν χρειάζονται**. Μετά την εγκατάσταση και το commit, όλα όσα περιείχαν βρίσκονται
στο git του `~/qrl-lab`. Μεταφέρεις:
1. **Το repo:** `git -C ~/qrl-lab bundle create ~/qrl-lab.bundle --all`. Περιέχει κώδικα, prompts, docs (STATE,
   DECISIONS, EXPERIMENTS, journal, claude-memory) και ρυθμίσεις.
2. **Ό,τι δεν είναι στο git:** το `.lab/`, δηλαδή μηνύματα, αιτήματα, ιστορικό runs, εκτίμηση κόστους, uploads και
   αποτελέσματα runs. Σταμάτα πρώτα τις υπηρεσίες (`systemctl --user stop qrl-dispatcher qrl-dashboard`), μετά
   `tar czf ~/qrl-lab-state.tgz -C ~/qrl-lab .lab`.
3. **Το worktree `code/`** (δικό του git) και όσα αποτελέσματα πειραμάτων είναι εκτός `.lab/`. Το
   `docs/EXPERIMENTS.md` λέει πού βρίσκονται. Και, αν χρειάζονται, οι αρχικοί φάκελοι (`~/simulations` κ.λπ.).
4. **Στο νέο μηχάνημα:** `git clone qrl-lab.bundle qrl-lab`, αποσυμπίεση του `.lab`, `bash tools/setup_dashboard_env.sh`,
   νέα σύνδεση στο `claude` και στο `codex login`, και `python3 tools/install_v03.py --apply`. Αυτό ξαναφτιάχνει τους
   κανόνες του Codex, το env και τις υπηρεσίες με τις νέες διαδρομές.
   Δεν μεταφέρονται ποτέ τα `.venv/`, κωδικοί, tokens και kubeconfig.
